# 基于 STM32F103 的 CAN 总线分布式气象监测系统

> 提示：本项目目前还在开发中，功能尚未完善，仅用于交流学习。

两块 STM32F103C8T6 通过 CAN 总线组成主从系统。主节点负责全网授时与人机界面，从节点采集
气压并周期上报。主节点跑 FreeRTOS，从节点用简单的双任务框架。

- **主节点**（node_id=0）：SHT30 温湿度 + DS3231 实时时钟 + OLED 三页界面 + EC11 旋钮切页
- **从节点**（node_id=1）：BMP280 气压 + 三位拨码设节点号
- **总线**：CAN 125 kbps，自定义 5 类应用帧，固定 8 字节 + 前 7 字节异或校验

---

## 1. 系统结构

```
  主节点 (id=0)                              从节点 (id=1)
  ├─ SHT30   温湿度   0x44                   ├─ BMP280  气压   0x76
  ├─ DS3231  实时时钟 0x68                   └─ 拨码    PB0~PB2 设节点号
  ├─ OLED    三页界面 0x3C
  └─ EC11    旋钮切页
         │                                          │
      软 I2C (PB6/PB7)                          软 I2C (PB6/PB7)
         │                                          │
   SN65HVD230 ──── CANH/CANL 125 kbps ──── SN65HVD230
                    120 Ω ×2 + 共地
```

| 链路 | 帧 ID | 方向与节奏 | 用途 |
|---|---|---|---|
| 校时 | `0x100` | 主 → 广播，60 s | 全网时间同步 |
| 环境上报 | `0x200` | 从 → 主，2 s | 温压湿数据 |
| 心跳查询 / 应答 | `0x300` / `0x301` | 主 10 s 发，从立即回 | 保活 |
| 阈值告警 | `0x400` | 从 → 主，状态翻转时 | 事件通知 |

---

## 2. 通信协议

固定 8 字节，多字节字段大端，第 8 字节为前 7 字节异或。
位时序 `Prescaler=16`、`BS1=15TQ`、`BS2=2TQ`、`SJW=1TQ`，即 72 MHz / (1+15+2) / 16 = **125 kHz**。

| 帧 | 字节布局 ([0] ~ [7]) |
|---|---|
| `0x100` 校时 | 年-2000 / 月 / 日 / 时 / 分 / 秒 / ms÷4 / XOR |
| `0x200` 环境 | node_id / temp_x10(2B) / 湿度(低7位)+状态(bit7) / press_x10(2B) / lux_x10 / XOR |
| `0x300` 查询 | 全 0 / XOR |
| `0x301` 应答 | node_id / 0 ×6 / XOR |
| `0x400` 告警 | node_id / 告警位图 / 0 ×5 / XOR |

毫秒存成 `ms÷4` 是为了压进 1 字节、保住 8 字节定长，分辨率降到 4 ms，对「误差 ≤1 s」够用。

**告警位图**：bit0 温度高(≥30℃) · bit1 温度低(≤10℃) · bit2 湿度高(≥85%) ·
bit4 气压低(≤1000 hPa) · bit5 气压高(≥1100 hPa)。各阈值带迟滞，避免临界值反复翻转。

## 3. 硬件与接线

| 器件 | 数量 | 说明 |
|---|---|---|
| STM32F103C8T6 最小系统板 | 2 | 72 MHz / 64 KB Flash / 20 KB RAM |
| SN65HVD230 CAN 收发器 | 2 | 3.3 V 供电，可与 F103 直连 |
| CH340 USB 转串口 | 2 | 主用 USART2，从用 USART1 |
| OLED SSD1306 0.96" | 2 | 0x3C（从节点本次未启用） |
| DS3231 实时时钟 | 1 | 0x68，仅主节点 |
| SHT30 温湿度 | 1 | 0x44，仅主节点 |
| BMP280 气压 | 1 | 0x76，仅从节点 |
| 120 Ω 电阻 | 2 | 总线两端各一个 |

主从模块不对称是设计决定：主节点是时间源加界面，气压由从节点采集后经 `0x200` 上报，
主节点不装 BMP280。

**引脚**

| 主节点 | 功能 | 从节点 | 功能 |
|---|---|---|---|
| PA2 / PA3 | USART2 调试串口 | PA9 / PA10 | USART1 调试串口 |
| PA11 / PA12 | CAN_RX / CAN_TX | PA11 / PA12 | CAN_RX / CAN_TX |
| PB6 / PB7 | 软 I2C SCL / SDA（开漏） | PB6 / PB7 | 软 I2C SCL / SDA（开漏） |
| PB4 | EC11 按键（需关 JTAG） | PB0~PB2 | 节点号拨码 |
| PB12 / PB13 | EC11 编码 A/B | — | — |
| PC13 | LED | PC13 | LED |
| PA13 / PA14 | SWD（保留） | PA13 / PA14 | SWD（保留） |

**三条接线纪律**

1. DS3231 的 VCC 必须 3.3 V。板载上拉会拉到 VCC，接 5 V 会打穿 PB6/PB7。
2. DS3231 板上的 200 Ω 充电电阻要拆掉，或改用 LIR2032。不可充电的 CR2032 会发热漏液。
3. 120 Ω 只在总线物理两端各一个；两块板必须共地。

## 4. 软件结构

| 层 | 文件 | 职责 |
|---|---|---|
| 协议层 | `can_proto.c/h` | 5 类帧 Build/Parse、异或校验（主从逐字节相同） |
| 驱动层 | `can_driver.c/h` | 滤波器、发送封装、接收中断、环形缓冲、喂狗 |
| 服务层 | `node_mgr.c/h` | 节点表、在线判据（仅主节点） |
| 器件层 | `sht30` / `bmp280` / `ds3231` / `oled` | 各器件读写 |
| 基础层 | `si2c` / `bsp_dwt` / `filter` | 软 I2C、微秒延时、滑窗滤波 |
| 应用层 | `main.c` / `oledui.c` / `app_can_task.c` | 任务与业务 |

**主节点任务**

| 任务 | 优先级 | 栈(字) | 周期 | 职责 |
|---|---|---|---|---|
| `WdgTask` | `osPriorityRealtime` → 6 | 256 | 200 ms | 按 3 位位图喂狗 |
| `CanRxTask` | `osPriorityHigh` → 5 | 512 | 20 ms | 收帧分发、心跳、60 s 校时 |
| `defaultTask` | `osPriorityNormal` → 3 | 640 | 200 ms / 1 Hz | 采集、告警、读 RTC |
| `UiTask` | `osPriorityBelowNormal` → 2 | 384 | 200 ms | 旋钮扫描、OLED 绘制 |

CMSIS-RTOS V1 的优先级有 +3 偏移：`fpriority = tskIDLE_PRIORITY + (priority - osPriorityIdle)`，
而 `osPriorityIdle = -3`，所以实际值等于枚举值加 3。

从节点只有采集和上报两条链路，节拍都是 2 s / 200 ms，两个任务足够。

**收帧链路**

```
CAN 中断 → 组装 CanFrame_t → 16 深环形缓冲（满则 drop++）
   → Task_CanRx 每 20 ms 抽干缓冲 → 按 ID 分发
```

## 5. 三处关键设计

**① 时间只能由主节点发。** DS3231 是 ±2 ppm 带温度补偿的晶振，MCU 的 HSE 典型 ±20~50 ppm，
用后者校准前者只会更差；DS3231 还有纽扣电池，掉电继续走。从节点软时钟的定位是
**测量工具**而非时间源：主从同时打印时间比差值，差值随时间线性增长即为两者的相对漂移。

**② 软时钟用绝对差值，不用每秒自增。**

```c
/* 每轮从基准点绝对重算 */
当前时间 = s_soft + (HAL_GetTick() - s_base_tick) / 1000
```

1 Hz 任务块的实测周期在 200.0~217 ms 之间浮动，且 `osDelay` 唤醒只晚不早，
每秒自增会让 3 分钟慢 2.7 s 且永不纠正。用绝对差值则某轮晚了下一轮自动补回。

**③ 超时后继续走时，只打 STALE 标记。** 验收要求「主节点断电 3 分钟再上电，从节点时间不乱」，
而 3 分钟超过 150 s 的失效阈值。若超时就冻结走时，一上电看到时间冻住，
肉眼和"时间乱了"无法区分。所以时间继续走，行尾追加 ` STALE`：

```
soft time 2026-10-18 15:40:07 age=3s
soft time 2026-10-18 15:43:07 age=183s STALE
```

一行日志同时验证软时钟独立走了 180 s、失效判据生效、主节点上电后新校时到达后 `age` 回落。

## 6. 构建与运行

- Keil MDK-ARM 5 + STM32CubeMX，编译器 ARMCC（C99 + MicroLib），调试器 ST-Link，串口 115200-8-N-1
- 打开 `WeatherMaster/MDK-ARM/WeatherMaster.uvprojx`，**Rebuild All**。
  不加 `-r` 时源码无时间戳变化会直接跳过并报 0 Error 0 Warning，`UV4` 退出码 1 也可能编译成功，以日志末行为准。

| 指标 | 主节点 | 从节点 |
|---|---|---|
| Error / Warning | 0 / 0 | 0 / 1 |
| Code | 24548 B | 17072 B |
| ZI-data | 15424 B | 14640 B |
| Total RW（RAM） | 15632 / 20480 B | 14848 / 20480 B |
| Total ROM | 27060 B | 19356 B |

**上电 LED 指示**：闪 2 下 = 进入初始化 · 闪 4 下 = DWT 与软 I2C 就绪 ·
闪 6 下 = OLED 就绪 · 常亮 = 进外设尾段 · 快闪 = 喂狗失败即将复位。
卡在「闪 4 下之后、闪 6 下之前」是软 I2C 通信问题。

## 7. 串口日志

| 日志 | 正常表现 | 异常含义 |
|---|---|---|
| `T sht=12ms` | 稳定十几毫秒 | 变大 = 软 I2C 被抢占 |
| `feed=12345` | 约 5 次/秒匀速增长 | 不涨 = 有位没签到，正在走向复位 |
| `Env node=1 T=.. H=..` | 每 2 秒一行 | 停 = CAN 收链断了 |
| `soft time ... age=3s` | 每秒递增 | 带 `STALE` = 超 150 s 没收到校时 |
| `time sync #12 -> ... ms=500` | 每 60 秒一行 | 不出现 = 分频逻辑或读 RTC 失败 |
| `ALARM 0x10` | 状态变化时出现一次 | 重复刷屏 = 缺迟滞 |

## 8. 进度与踩坑

| 已通过 | 待做 |
|---|---|
| 双节点 CAN 对通、连发 100 帧 drop=0 | 主节点断电 3 分钟再上电测试 |

| 三页界面切换、60 s 校时链路 | 从节点栈水位基线 |
| 从节点软时钟、拔线 6 s 判离线 | 演示视频 |
| 五个对象栈水位 ≥25% | — |

**踩过的坑**

| 问题 | 原因 |
|---|---|
| 板子每几秒复位一次 | `fputc` 里互斥量拿两次，非递归互斥量第二次永久阻塞，喂狗任务被卡死 |
| OLED 整屏刷新 2169 ms | `delay_us` 每次调用做 64 位除法，软 I2C 一个字节调几十次。改为缓存每微秒周期数后降到 190~350 ms |
| 上电头 1 秒心跳应答 `node=0` | `node_id` 赋值放在 1 Hz 块里，心跳在更快的收帧循环里用它。附带发现 CAN 硬件自动重传会让离线期间的帧在节点上线后才送达 |
| PB4 按键没反应 | PB4 复位后是 JTAG 的 NJTRST，不调 `__HAL_AFIO_REMAP_SWJ_NOJTAG()` 则 EXTI4 完全不触发 |
| CAN 收不到任何帧 | F103 未激活任何滤波器组时默认拒收全部，必须至少激活一个掩码全 0 的全通组 |
| `case` 后声明变量报 undefined | `case` 标签后不能直接跟声明，必须用 `{ }` 开块 |
